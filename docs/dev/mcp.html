Automation API (MCP) 自动化 API（MCP）

SXSEditor exposes a loopback HTTP bridge so agents and scripts can drive the editor. The stdio MCP server (npm run mcp) wraps the same API; both share one schema.

SXSEditor 暴露一个回环 HTTP 桥，使智能体与脚本可以驱动编辑器。stdio MCP 服务器（npm run mcp）包装同一套 API；两者共用同一份架构。

POST /automation `{method, params, requestId?, async?}``{method, params, requestId?, async?}`

The bridge listens on 127.0.0.1 only — non-loopback clients are rejected with FORBIDDEN. Discovery file: <userData>/mcp-endpoint.json (mode 0600) with port, token (the default token only), pid, version, schemaVersion, and urls. Named tokens stay in <userData>/mcp-tokens.json — readers of the discovery file cannot impersonate every configured client. <userData> is %APPDATA%/SXSEditor on Windows and ~/.config/SXSEditor on Linux.

桥仅监听 127.0.0.1——非回环客户端会被 FORBIDDEN 拒绝。发现文件：<userData>/mcp-endpoint.json（权限 0600），含 port、token（仅默认 token）、pid、version、schemaVersion 与 urls。命名 token 保存在 <userData>/mcp-tokens.json——发现文件的读取者无法冒充每个已配置的客户端。<userData> 在 Windows 上为 %APPDATA%/SXSEditor，Linux 上为 ~/.config/SXSEditor。

Calling 调用 

EP=$(node -p "require(process.env.HOME+'/.config/SXSEditor/mcp-endpoint.json').port")
TOKEN=$(node -p "require(process.env.HOME+'/.config/SXSEditor/mcp-endpoint.json').token")
curl -s localhost:$EP/automation -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{"method":"project.get","params":{"includeNotes":false}}'

Every response is {ok, result, warnings?, requestId?} or {ok:false, error:{code, message, field?, hint?, details?}}.

每个响应都是 {ok, result, warnings?, requestId?} 或 {ok:false, error:{code, message, field?, hint?, details?}}。

ℹ️

Limits. Rate limit is 120 requests per 10-second window (RATE_LIMITED with a retry hint). Request bodies are capped at 32 MiB. A synchronous call times out after 60 s (TIMEOUT); long methods get 600 s.

限额。限速为每 10 秒窗口 120 次请求（超限返回 RATE_LIMITED 并带 retry 提示）。请求体上限 32 MiB。同步调用 60 秒超时（TIMEOUT）；长时方法为 600 秒。

Jobs 后台任务

Add "async": true to POST /automation for long methods (export, synthesis, MIDI extraction). The call returns 202 {jobId, poll}; poll GET /jobs/<id> for status (queued → running → completed / failed / cancelled) plus result or error.

对长时方法（导出、合成、MIDI 提取）在 POST /automation 中加 "async": true。调用返回 202 {jobId, poll}；轮询 GET /jobs/<id> 获取 status（queued → running → completed / failed / cancelled）以及 result 或 error。

Session & File Access 会话与文件访问

session.grantRoot

Grant the automation session read/write access to a directory tree.

授予自动化会话对某目录树的读写权限。

The directory is validated (no system/sensitive/hidden paths) and added to the same in-memory allow-list the file dialogs use. Grants live until the app exits or session.revokeRoots is called.

目录会经过校验（拒绝系统 / 敏感 / 隐藏路径），并加入文件对话框使用的同一内存允许列表。授权持续到应用退出或调用 session.revokeRoots 为止。

target: main · mutates project目标：main · 修改项目

Parameter参数 Type / notes类型 / 说明
path string · required · Absolute directory pathstring · 必填 · 目录绝对路径 
{

  "params": {
    "path": "${path}"
  }

Notes 备注

  • File paths must be inside a directory granted with session.grantRoot (or one of the app's default save roots). Grants are session-scoped and disappear on exit. The renderer additionally self-authorizes individually whitelisted media/project files (.wav, .sxssinger, .sxsproj, .mid, .lrc) through the same path rules as the dialogs.文件路径必须位于用 session.grantRoot 授权的目录内（或应用默认保存根目录之一）。授权随会话生效，退出即失效。渲染进程另外会通过对话框相同的路径规则，自行放行个别白名单媒体 / 项目文件（.wav、.sxssinger、.sxsproj、.mid、.lrc）。
  • project.apply validates every operation before mutating and rolls back on failure (atomic: false opts out). dryRun: true returns the plan without touching state.project.apply 会在修改前校验每个操作，失败即回滚（atomic: false 可退出回滚）。dryRun: true 只返回计划，不触碰状态。
  • Note ids are derived from note content, so identical payloads produce identical ids.音符 id 由音符内容派生，因此相同的载荷会产生相同的 id。
