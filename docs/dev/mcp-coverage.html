MCP Coverage MCP 覆盖范围

The automation surface has 52 methods, all exposed by the stdio server (71 tool names including aliases and multi-action helpers). Being callable is not the same as being sufficient, so this page is organised by scenario rather than by function, and it identifies the tasks that MCP does not cover.

自动化接口共 52 个方法，stdio 服务器将其全部暴露（含别名与多动作工具共 71 个工具名）。可调用不等于可完成，因此本页按使用场景而非方法清单组织，并说明 MCP 未覆盖的任务。

ℹ️

Parameter validation follows the editor's controls rather than a separate set of limits: per-note vibrato accepts depth 0–200 cents and rate 2–10 Hz, matching the sliders in the fragment editor and the values imported from Synthesizer V projects. Values outside those ranges fail schema validation instead of being silently clamped. The pipeline.* domain reports and loads local ONNX model groups; it does not install or trust plugins.

参数校验沿用编辑器的控件范围，而不是另设一套上限：音符级颤音的幅度为 0–200 音分、频率为 2–10 Hz，与片段编辑器的滑杆以及从 Synthesizer V 工程导入的取值一致。超出范围的值无法通过接口的参数校验，也不会被静默裁剪。pipeline.* 域用于查询与加载本地 ONNX 模型组，不涉及插件的安装与信任。

Not Covered 未覆盖

Scenario场景 Reason未覆盖原因 What to do instead替代做法
Installing, enabling, trusting or removing plugins安装 / 启用 / 信任 / 卸载插件 These are the decisions that grant code execution. Exposing them to a remote caller would mean an agent could widen its own permissions — the one thing the permission model exists to prevent.这几个动作的实质是「授权别人执行代码」。交给外部调用方，等于让 agent 自己给自己扩权——而权限模型存在的意义正是拦住这件事。 The manager window (Plugins → Manage Plugins…), or the CLI for the parts that do not install code: plugin list, plugin verify, plugin trust, plugin policy, plugin market preview.管理器窗口（插件 → 插件管理器…）；不涉及装代码的部分走 CLI：plugin list、plugin verify、plugin trust、plugin policy、plugin market preview。
Creating a singer from scratch从零创建歌手 The wizard is a multi-step UI over a model run with human judgement in the middle (picking a take, adjusting a timbre). singer.import covers bringing in a finished singer, not producing one.这个向导是多步 UI，中间夹着模型推理与人的判断（挑一条、调音色）。singer.import 只解决「导入成品歌手」，不解决「生成一个」。 Run the wizard once, then automate against the resulting singer with project.apply.手动跑一次向导，之后用 project.apply 对生成出来的歌手做自动化。
Menu-level commands菜单级命令 Recent files, "open logs folder", "check for updates" are shell actions with no project semantics. Anything that touches a file can be done with an explicit path instead.最近打开、打开日志目录、检查更新都属于外壳动作，没有工程语义。凡是涉及文件的，都能用显式路径完成。 Use project.loadFrom / saveTo with absolute paths after session.grantRoot.先用 session.grantRoot 授权目录，再用绝对路径走 project.loadFrom / saveTo。
Reading the plugin activity log读取插件活动日志 The log is a UI surface for the person deciding whether to trust something. It is not a monitoring feed, and it contains package paths.这份日志面向的是「要不要信任它」的人，不是监控数据源，而且里面有包路径。 Open the manager's third tab, or read the log file under <userData>/logs.看管理器第三个页签，或直接读 <userData>/logs 下的文件。
ℹ️

The first item is a design decision. If it were to be exposed, it would require a separate, explicitly granted capability rather than additional methods on the existing token.

第一项属于设计决定。若要开放，应作为单独的显式授权能力，而不是在现有 token 上增加方法。

Two implementation details 两个实现细节

Discovery depends on userData 端点发现依赖 userData

The stdio server locates the running app by reading mcp-endpoint.json from the platform's standard userData path. If you start the app with --user-data-dir=/tmp/something, that file is written there instead and discovery silently fails with ECONNREFUSED against a stale port. Point the server at the right file:

stdio 服务器从平台标准的 userData 路径读取 mcp-endpoint.json，以定位正在运行的应用。若应用以 --user-data-dir=/tmp/something 启动，该文件会写入该目录，默认发现路径将读到旧端口并返回 ECONNREFUSED。此时需将服务器指向正确的文件：

SXSEDITOR_MCP_ENDPOINT=/tmp/something/mcp-endpoint.json node <server absolute path>/sxseditor-mcp.js

In a packaged build the server is <install>/resources/mcp/sxseditor-mcp.js; in a source tree it is <repo>/mcp/sxseditor-mcp.js. Help → MCP Connection… prints the exact paths for the current installation and the configuration blocks for Claude Code, WorkBuddy, OpenCode and Codex. The four clients do not share one JSON shape: OpenCode takes a command array and Codex takes a TOML [mcp_servers.*] table.

安装包中服务器位于 <安装目录>/resources/mcp/sxseditor-mcp.js，源码树中位于 <仓库>/mcp/sxseditor-mcp.js。帮助 → MCP 连接… 会给出当前安装的实际路径，以及 Claude Code、WorkBuddy、OpenCode、Codex 四端各自的配置片段。四端并不共用同一种 JSON：OpenCode 的 command 是数组，Codex 使用 TOML 的 [mcp_servers.*] 表。

Model errors keep their classification 模型错误保留原有分类

Model-domain codes are translated into MCP codes, with the original kept in details.modelCode. "No endpoint bound for this task" arrives as PRECONDITION_FAILED — retrying it unchanged is pointless, and an agent can tell that apart from INTERNAL:

模型域的错误码会翻成 MCP 码，原始码留在 details.modelCode。「这个 task 没有绑定端点」返回 PRECONDITION_FAILED——原样重试没有意义，而 agent 能把它与 INTERNAL 区分开：

{
  "ok": false,
  "error": {
    "code": "PRECONDITION_FAILED",
    "message": "task=chat 没有默认端点",
    "hint": "configure an endpoint for this task in Settings → Models",
    "details": { "modelCode": "NEED_ENDPOINT", "retryable": false }
  }
}
