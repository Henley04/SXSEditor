Writing a Plugin: End to End 编写插件：从零到发布

This page covers the complete workflow: what to decide before writing code, the seven steps from an empty folder to a signed package, and how to keep the result maintainable. The normative contract for singing backends is in Plugin Backends; reference material on models, services, data access and secrets is linked at the end.

本页说明从编写到发布的完整流程：动手前的设计决策、从空目录到签名包的七个步骤，以及如何让插件保持可维护。歌声后端的规范性契约见插件后端；模型、服务、数据访问与密钥的参考文档列在文末。

ℹ️

The commands and outputs on this page were taken from an actual build.

本页的命令与输出均取自实际构建。

Design Goals 设计目标

The system follows from five constraints rather than preference; each one rules out an approach that would otherwise look simpler.

系统设计由五条约束决定，每一条都排除了一种看似更简单的做法。

Goal目标 What it rules out它否掉了什么
Capability first, code second先声明能力，再跑代码 A plugin that can call ctx.project.apply must have declared project: ["write"]. If permissions were inferred from what the code happens to call, the install dialog could not tell the user anything true, and revoking a permission after the fact would be impossible. 能调 ctx.project.apply 的插件必须声明过 project: ["write"]。如果权限靠「代码里碰巧调了什么」推断，安装对话框就没有一句真话可讲，事后想收回权限也无从下手。
Failure must be locatable失败必须可定位 A hung plugin cannot be allowed to hang the editor, so plugins run off the main thread and are terminated at the deadline. Every install, call and refusal is written to the audit log with a machine-readable code. 一个卡死的插件不能把编辑器一起拖死，所以插件跑在主线程之外，到点直接终止。每次安装、调用、拒绝都带机器可读的错误码写进审计日志。
Trust must be decidable信任必须可判定 "Signed by Example Studio" is a claim inside the package. The manager shows a key fingerprint instead, and the signature covers a manifest of file hashes — so changing one byte invalidates the whole thing. 「由 Example Studio 签名」是包自己说的话。管理器显示的是密钥指纹，签名覆盖的是文件哈希清单——改一个字节，整条链就断。
Portable by construction天生可移植 Zip entry names are just strings. Main.js and main.js are two files on Linux and one on NTFS, so the same package would install different content on different machines while both verify. Names are validated on read and write. zip 条目名只是字符串。Main.js 与 main.js 在 Linux 上是两个文件，在 NTFS 上是一个——同一个包在两台机器上装出不同内容，却都能验签通过。所以读写两侧都校验条目名。
The user sees the price up front代价要提前可见 Permissions, publisher fingerprint and signature state appear before install, not after. Network access for models is brokered by the host, so a plugin cannot quietly ship a hard-coded endpoint and its own key. 权限、发布者指纹、签名状态都在安装前出现，不是装完再说。模型出网由宿主代发，插件没法偷偷内置一个端点和自己的密钥。

Two Shapes of Plugin 两种插件形态

Pick the shape before writing the manifest — the two are not interchangeable, and the fields do not overlap.

先定形态再写 manifest：两者不能互换，字段也不重叠。

apiVersion: 1 apiVersion: 2
Purpose用途 A singing backend that replaces the built-in synthesiser替换内置合成器的歌声后端 A capability pack: commands, panels, services, automation, model access能力包：命令、面板、服务、自动化、模型调用
Key fields关键字段 trackKinds, capabilities, main permissions, contributes, main
Template模板 plugins/example-concat — sine/triangle/pulse concatenation, no model plugins/example-hello — command + panel + toolbar + settings
Deep dive深入 Plugin Backends (contract v1) Services, Data, Models, Automation

The Full Pipeline 完整流程

0. Prerequisites 0. 前置条件

Node 20+, a checkout of the repository, and dependencies installed. The packaging script is plain Node — it does not need Electron running, which is what makes it usable in CI.

Node 20+、一份仓库检出、依赖装好。打包脚本是纯 Node 的，不需要 Electron 在跑——所以它能直接放进 CI。

git clone https://github.com/Henley04/SXSEditor
cd SXSEditor
npm ci

1. Start from a template 1. 从模板开始

Copy a template out of plugins/ and rename the folder. The folder name must equal the id in the manifest; the installer refuses anything else, because two plugins claiming one id would make "disable plugin X" ambiguous.

把 plugins/ 下的模板复制出来改名。目录名必须与 manifest 的 id 一致——安装器不接受别的，因为两个插件共用一个 id 会让「停用 X」这句话失去指向。

cp -r plugins/example-hello plugins/my-plugin
$EDITOR plugins/my-plugin/manifest.json

2. Write the manifest 2. 写 manifest

The smallest v2 manifest that can actually do something — one command, exposed to automation, nothing else:

能真正干活的最小 v2 清单——一个命令、允许外部调用，别的都不要：

{
  "apiVersion": 2,
  "id": "my-plugin",
  "name": "My Plugin",
  "version": "0.1.0",
  "main": "main.js",
  "engines": { "app": ">=2.0.0" },
  "permissions": { "automation": ["expose"] },
  "contributes": {
    "commands": [
      { "id": "ping", "title": { "en": "Ping", "zh-CN": "打个招呼" } }
    ],
    "automation": { "methods": ["ping"] }
  }
}
⚠️

A command listed under contributes.automation.methods becomes callable from MCP and the CLI. That is a permission change, not a detail: an agent can then run it without you clicking anything. Leave it out until you actually need it.

写进 contributes.automation.methods 的命令会被 MCP 与 CLI 调用，这等于改权限而不是改配置：外部 agent 可以在没人点按钮的情况下执行它。用不上就先别写。

3. Implement the entry module 3. 写入口模块

A v2 entry exports activate(ctx) and optionally deactivate(). Every host capability is a method on ctx; anything not on ctx is not reachable, no matter what the code tries.

v2 入口导出 activate(ctx)，可选 deactivate()。宿主能力都是 ctx 上的方法；不在 ctx 上的东西，代码怎么写也够不到。

exports.activate = async (ctx) => {
  ctx.commands.register('ping', async () => {
    const project = await ctx.project.read();
    ctx.ui.notify(`bpm=${project.bpm}`);
    return { ok: true };
  });
};

Return values matter: MCP clients receive exactly what the command returns, serialised to JSON. Throwing is how you fail — the host turns the error into a code the caller can branch on, and keeps the message for the log.

返回值是有用的：MCP 客户端收到的就是命令返回的那个对象（序列化成 JSON）。失败靠抛异常——宿主把错误翻成调用方可以分支判断的错误码，同时把消息留在日志里。

4. Run it for real 4. 真机跑起来

Two ways in, and they check different things. The manager shows what a user will see; the CLI shows what an agent will see.

两种方式验证的内容不同：管理器呈现用户看到的信息，CLI 呈现 agent 看到的信息。

# 打包并安装到当前用户
node scripts/package-plugin.js plugins/my-plugin -o dist-plugins

# 或者直接用 CLI 看装了哪些、暴露了哪些方法
npm run cli -- --cli plugin list
npm run cli -- --cli plugin methods
npm run cli -- --cli plugin call my-plugin.ping --json

5. Package 5. 打包

Do not zip by hand. The package contains a checksums.json that must match the files byte for byte; hand-maintained lists drift, and the installer will reject a drifted package with a message that looks like corruption.

不要手工压缩。包里有一份 checksums.json，必须与文件逐字节对应；手工维护必然漂移，而安装器只会把它当成包损坏报出来。

node scripts/package-plugin.js plugins/my-plugin -o dist-plugins
# 已生成 dist-plugins/my-plugin-0.1.0.sxsp（4 个文件，2.6 KB）
# 未签名：安装时会被标注为"未签名"

6. Sign 6. 签名

Generate a key pair once, keep the private key out of the repository, and sign every release. The signature covers the checksum manifest, and the manifest covers every file — changing one byte breaks the chain at the first link.

密钥对只生成一次，私钥不要进仓库，每个版本都签。签名覆盖哈希清单，清单覆盖每个文件——改一个字节，链在第一节就断了。

node scripts/package-plugin.js --gen-key keys/
node scripts/package-plugin.js plugins/my-plugin -o dist-plugins \
  --key keys/plugin-signing.key --publisher "Example Studio"

# 已签名 keyId=ed25519-2e37e4d1a26007fb publisher=Example Studio

Ship the public key (*.pub) alongside the package. Users who have not trusted it yet get one prompt showing the fingerprint; after that the key is remembered by fingerprint, not by publisher name.

公钥（*.pub）随包一起发。还没信任它的用户会看到一次带指纹的确认；确认之后记住的是指纹，不是发布者名字。

7. Publish to a market index 7. 发到市场索引

An index is a static JSON file. It lists packages with their sha256 and size; the client re-checks both against the downloaded file, because the index is the source's claim, not evidence.

索引就是一个静态 JSON。它列出包与 sha256、大小；客户端下载后会自己再算一遍——索引只是源的自述，不是证据。

{
  "schema": "sxs-plugin-index-v1",
  "plugins": [
    {
      "id": "my-plugin",
      "name": "My Plugin",
      "version": "0.1.0",
      "url": "https://example.com/plugins/my-plugin-0.1.0.sxsp",
      "sha256": "e9936ca6a05cbcea…",
      "size": 2710,
      "publisher": "Example Studio"
    }
  ]
}

Then either add the index in the manager or from the terminal:

然后在管理器里添加索引，或在终端里加：

npm run cli -- --cli plugin market add https://example.com/plugins/index.json --name "My Source"
npm run cli -- --cli plugin market search my-plugin
npm run cli -- --cli plugin market preview my-plugin
npm run cli -- --cli plugin market install my-plugin --yes

preview downloads the whole package and runs the same inspection the installer uses — signature, permissions, portability — and stops before writing anything. install without --yes refuses; that flag is the difference between "show me" and "do it".

preview 会下载整包、走与安装器同一套检查（签名、权限、可移植性），但在落盘前停下。install 不带 --yes 会被拒绝，该开关用于区分预览与执行。

Best Practices 最佳实践

Each of these comes from a failure that actually happened during development, not from a style guide.

以下每条规则对应一种具体的失效场景，而非一般性风格建议。

Do做法 Because原因
Never busy-wait or run unbounded synchronous work不要忙等，不要在插件里跑无界的同步任务 In inprocess mode a 2-second synchronous loop survives a 300 ms timeout — the timer cannot fire because the loop owns the thread. In worker mode it is killed, which is better, but you still lose the call.inprocess 模式下 2 秒的同步忙等在 300ms 超时下照样跑完——定时器根本没机会触发。worker 模式下它会被杀掉，这更好，但这次调用还是废了。
Declare the narrowest permission set that works按最小可用声明权限 Permissions are shown before install and checked at every call. A plugin asking for project: ["write"] when it only reads will be noticed by users, and rightly so.权限在安装前展示、每次调用都校验。只读却要 project: ["write"] 的插件会被用户看出来，而且应该被看出来。
Keep secrets out of the package密钥不要进包 A .sxsp is a zip; anyone who downloads it can read every byte. Use ctx.secrets, which stores values encrypted per installation..sxsp 就是 zip，下载者能读每一个字节。用 ctx.secrets，它按安装实例加密存储。
Report progress for anything over a second超过一秒的操作要报进度 The host can only cancel what it can observe. A silent long task looks like a hang, and users kill the app instead of waiting.宿主只能取消它看得见的东西。没有进度的长任务看起来就是卡死，用户会直接杀进程而不是等。
Fail with a sentence a user can act on失败时给用户一句能照做的话 PERMISSION_DENIED alone tells nobody what to do. "Enable file access for this folder in Settings → Plugins" does.只抛 PERMISSION_DENIED 没人知道该干嘛。「在 设置 → 插件 里为这个目录授权」才知道。
Treat ctx.project.apply as the only way to change the project改工程只走 ctx.project.apply Direct mutation bypasses validation and the undo stack; the change disappears on the next project load, which looks like data loss.直接改对象绕过校验和撤销栈；下次加载工程时改动消失，看起来就像丢数据。
Use deactivate() to release timers, watchers and child processes在 deactivate() 里释放定时器、监听与子进程 Disabling a plugin must actually stop it. A leaked interval keeps the process alive and keeps writing into the log after the user turned it off.停用必须真的停。漏掉的 interval 会让进程活着，并在用户关掉之后继续往日志里写。
Test with the packaged file, not the source folder用打好的包测，不要只测源码目录 Packaging adds checksums.json and normalises names. A plugin that works in-place can still fail to install — that is exactly what the packager is for.打包会加 checksums.json 并归一化文件名。源码能跑的插件照样可能装不上——打包器存在的意义就在这里。
Version the contract为契约声明版本 engines.app is checked at load. Bumping a major version without it means old builds try to load a manifest they cannot understand.engines.app 在加载时校验。改了主版本却不写它，旧构建就会去加载自己看不懂的清单。
Watch the activity log while developing开发时盯着活动日志 Every load, call, refusal and crash lands there with a code. It answers "did my command even run?" faster than any breakpoint.每次加载、调用、拒绝、崩溃都带码落在这里。回答「我的命令到底跑没跑」比断点快得多。

Pre-release Checklist 发布前检查清单

  • Folder name equals id; version bumped; engines.app reflects the API you actually use.目录名等于 id；版本号已升；engines.app 与实际用到的 API 对得上。
  • Every permission in the manifest is used, and nothing used is missing from it.清单里的权限都用得上，用到的东西也都写进了清单。
  • No absolute paths, no drive letters, no names differing only by case inside the package.包内没有绝对路径、盘符，也没有仅大小写不同的文件名。
  • Installed from the packaged .sxsp on a clean profile, not from the source folder.在干净的用户数据里用打好的 .sxsp 装过一次，而不是只在源码目录跑过。
  • Disable and uninstall both leave no stray process, timer or file handle.停用与卸载都不留下残留进程、定时器或文件句柄。
  • The activity log reads cleanly after a normal run — no unexplained rejections.正常跑一遍之后活动日志是干净的，没有解释不了的拒绝记录。
