# 插件界面的无障碍（a11y）与主题对比度

> 适用版本：M6 第 3 段（2026-11-05）。范围是**插件管理器窗口**与**插件面板宿主**，
> 以及支撑它们的**主题 token**。宿主其它窗口的键盘路径不在本轮范围内。

## 1. 为什么这一段不能靠"看着还行"

插件系统此前所有 UI 决策都是"能看清就行"：徽标用主题的绿色、警告用琥珀色、
选中态用强调色。这些颜色是给**填充**设计的 —— 画一条下划线、一个圆点、一块底色。
一旦它们被拿来写 11px 的文字，在浅色主题上就是：

| 组合 | 修前 | 修后 |
|---|---|---|
| 成功绿文字 / soft 底 | 1.93:1 | 5.4:1 |
| 警告黄文字 / 面板 | 1.58:1 | 6.0:1 |
| 危险红文字 / soft 底 | 2.72:1 | 5.9:1 |
| 强调青文字 / 面板 | 2.22:1 | 5.5:1 |
| 白字 / 青色主按钮 | 2.36:1 | 6.7:1（改成深墨字） |
| 禁用文字 / 按钮底 | 2.24:1 | 3.4:1 |

这些值不是猜的，是 `scripts/audit-contrast.js` 算的。截图上看不出来：11px 的浅绿
在 27 寸屏上"似乎能读"，在笔记本强光下就是一片糊。

## 2. 对比度：一个能跑的判据

```bash
npm run audit:contrast     # 表格输出，有 warn 或 fail 时退出码 1
node scripts/audit-contrast.js --json   # 机器可读
```

脚本按 WCAG 2.1 算：正文 4.5:1、大字 3:1；禁用态在 WCAG 里是豁免项，这里仍以
**3:1 作为"最低可辨识"下限**，因为"禁用"不等于"看不见"。

审计的组合写在 `PAIRS` 里，目前 95 组（19 组 × 5 套主题）。加一个 token 就要想清楚
它压在哪几个背景上，把组合补进 `PAIRS` —— 否则新 token 没人审。

`test/themeContrast.test.js` 把这件事变成回归测试：任何一套主题掉到 AA 以下都会
让测试失败，而不是等用户抱怨。

### 2.1 填充色与文字色必须分开

修法不是"把绿色调深一点"，而是承认两组 token 各有用途：

| 用途 | token | 例子 |
|---|---|---|
| 填充 / 圆点 / 下划线 | `--accent`、`--success`、`--warning`、`--danger` | 选中下划线、软色底、状态点 |
| 文字 | `--accent-fg`、`--success-fg`、`--warning-fg`、`--danger-fg` | 徽标文字、链接、图标 |

同一条规则也适用于"压在实心底上的文字"：`--fg-on-accent` / `--fg-on-danger`。
ACG 主题里青色 `#3fb8c9` 太亮，白字只有 2.36:1，所以它的 `--fg-on-accent` 改成
深墨 `#12262b`（6.66:1）——**青色按钮 + 深墨字**，仍然是那个青色，仍然扁平。

本轮把全项目 35 处 `color: var(--accent)`、44 处 `color: var(--success|warning|danger)`
统一换成了 `-fg` 变体。这不是插件专用改动：token 是全局的，改一处九个窗口都变。

### 2.2 顺带修掉的"从来没人定义"的 token

`.pm-btn-danger` 与错误 toast 一直写着：

```css
color: var(--fg-on-danger, var(--fg-on-accent, #ffffff));
```

而 `--fg-on-danger` **在四套主题里都不存在**。它只是靠三层兜底拿到了白色，
在珊瑚红底上 3.38:1。这一轮把它变成真 token，每套主题各自给值（浅色主题把危险底色
也压深到 `#b84a4a`，白字 5.1:1）。

## 3. 键盘与焦点

### 3.1 选项卡是一组单选，不是一排按钮

```html
<nav class="pm-tabs" role="tablist" aria-label="插件页面">
  <button role="tab" id="pmTabInstalled" aria-controls="pmPaneInstalled"
          aria-selected="true" tabindex="0">…</button>
```

- **roving tabindex**：整组只占一个 Tab 位，组内 `←/→` 移动、`Home/End` 跳首尾；
- **自动激活**：这三个面板都是本地即时视图，切换没有副作用，多一次回车只会更累；
- **焦点跟着选中项**：否则 tabindex 挪到新项后，焦点还留在旧项（`tabindex=-1`）上；
- 面板用 `aria-labelledby` 指回它的 tab，`tabindex="0"` 让键盘用户能直接滚动内容。

### 3.2 列表整段重建，焦点必须跟着走

管理器每次收到主进程 `sync` 就 `refresh()`，而 `renderInstalled()` 是
`textContent = ''` 再重建 —— 正在聚焦的按钮随之消失，焦点掉到 `body`，
下一次 Tab 从页面开头重新数。

规则：**渲染前记下"焦点在哪张卡的哪个按钮上"（`data-act`），渲染后放回去**。
显式意图（刚装好某插件、刚展开确认条）优先于快照。

由此得到两个交互细节：

| 动作 | 焦点去哪 | 为什么 |
|---|---|---|
| 点"卸载"展开确认条 | 落到**取消**按钮 | 破坏性操作默认聚焦最不危险的那个 |
| 取消确认 / 卸载失败 | 回到那一条的"卸载"按钮 | 用户还在这一条上 |
| 卸载成功（卡片消失） | 列表首项；列表空了则空态 | 总比掉到 `body` 强 |
| 信任横幅出现 | 横幅本身（`tabindex=-1`） | 读屏念标题+指纹；不默认聚焦"信任并安装"，那等于诱导按回车放行 |
| 信任并安装成功 | 新装的那张卡的"停用"按钮 | 用户既知道装成了，也知道装到哪了 |
| 取消信任 | "安装插件…" | 动作的起点 |

### 3.3 插件面板：能做的是"归还"，不是"陷阱"

面板是 `sandbox="allow-scripts"` 且**没有** `allow-same-origin` 的 iframe，
宿主读不到插件文档里的可聚焦元素，也没法拦 Tab。所以这里不做焦点陷阱
（做了也是假的：Tab 会从 iframe 里跑出去），做两件真事：

1. 打开时记下触发元素，关闭时 `focus()` 回去；
2. `load` 之后再 `iframe.focus()`，把键盘交给面板（文档就绪前 focus 会被忽略）。

卸载路径（`destroy: true`）不还焦点：触发卸载的控件本身可能已经不在了。

## 4. ARIA 与动效

| 位置 | 做法 |
|---|---|
| 选项卡 / 面板 | `role=tablist/tab/tabpanel`、`aria-selected`、`aria-controls`、`aria-labelledby` |
| 信任横幅 | `role="alert"` + `aria-labelledby`/`aria-describedby`（只在"由隐藏变可见"那一下抢焦点） |
| toast | `role="status" aria-live="polite" aria-atomic="true"`，节点常驻、只切 `hidden` |
| 插件面板 iframe | `title` = 插件名 + 面板名 |
| 停用的插件卡片 | 不再整块 `opacity: .72`（会把正文一起压到 4.5 以下），改凹陷底色 + 虚线边 |
| 动效 | `@media (prefers-reduced-motion: reduce)` 关掉三处颜色过渡 |

## 5. 边界（写在明处）

- **没有真机读屏验证**：沙箱里没有 NVDA / VoiceOver / Orca，本轮只做到"属性正确、
  键盘路径可用、焦点不丢"。真机朗读效果仍需在有读屏的机器上过一遍。
- **只覆盖管理器与面板宿主**：宿主其它窗口（设置、资源管理器等）的键盘可达性没审，
  但它们会因 token 变化而受益（对比度是全局的）。
- **强调色下划线没按 3:1 处理**：ACG 的 `--accent` 在面板上只有 2.2:1，作为 2px 下划线
  低于非文本对比度要求。这里刻意不加深它（那是整个应用的品牌色），改用"文字颜色 +
  字重 + 下划线"三个通道共同表达选中，不依赖那一条线的颜色单独承载状态。
- **iframe 内的可访问性由插件作者负责**：宿主只能给 frame 一个标题。
- **`--fg-disabled` 只保到 3:1**：WCAG 豁免禁用控件，这里只保证"看得见轮廓"，
  不保证"读得舒服"。占位符（`--input-placeholder`）继承了它，因此也停在这个下限。
