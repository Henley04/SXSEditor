v2.0.3 v2.0.3

New Features 新功能

  • Plugin backends (extension tracks) — tracks can now be rendered by a third-party backend instead of the built-in SoulX-Singer model. A plugin is an ordinary folder copied into %APPDATA%\SXSEditor\plugins; the add-singer dialog gains a Plugins section with Open plugin folder / Reload and one entry per track kind the plugin declares. Plugin tracks use the same fragment editor (a plugin may opt into MIDI or MIDI-partial editing), define their own timbres and parameters, show a blocking preparation overlay with its own progress text and an optional cancel button, and can be mixed with built-in tracks in one project. Removing a plugin keeps its tracks in the project but reports a clear error instead of silently falling back to the built-in model. Nothing is preinstalled.插件后端（扩展轨道）——轨道现可交给第三方后端渲染，而不必使用内置的 SoulX-Singer 模型。插件就是一个普通文件夹，复制到 %APPDATA%\SXSEditor\plugins 即可；「添加歌手」对话框新增插件分区，提供「打开插件目录」/「重新加载」，以及插件声明的每种轨道种类的入口。插件轨道使用同一套分片编辑器（插件可声明 MIDI 或 MIDI 部分编辑模式），音色与参数由插件自己定义，准备阶段显示带自身文案、进度与可选取消按钮的浮层；同一工程内可与内置轨道混用。删除插件后，使用该后端的轨道仍保留在工程中，但会明确报错，不会静默回退到内置模型。应用不预装任何插件。
  • Timbre post-processing lane — the Timbre lane in the fragment editor's bottom panel (key 6), previously a disabled placeholder, is now fully functional. Seven per-frame automation parameters: F0 smoothing (blend toward a Savitzky-Golay filtered copy, 7-frame cubic window), F0 outlier removal (median window, 0–9 frames), transition overshoot and transition length (cubic Bézier on detected pitch leaps above 50 cents / 75 cents of median level change), spectral interpolation at note and phoneme boundaries (±3 frames, raised-cosine weighted), and time / frequency Gaussian smoothing on the Mel spectrogram. Each parameter owns a separate curve with its own unit and scale; an empty curve means "constant" and follows the inspector slider, and the banner switches between Manual and Auto. Presets (Off / Gentle / Standard / Strong) apply a tested combination. Everything defaults to Off, so existing projects keep bit-identical output.音色后处理车道——分片编辑器底部参数面板中原本占位禁用的「音色」lane（快捷键 6）现已完整可用。七个逐帧自动化参数：F0 平滑强度（向 Savitzky-Golay 滤波结果混合，7 帧三次窗口）、F0 异常值抑制（中值窗口 0–9 帧）、过渡过冲与过渡时长（对检出的音高跳变套用三次贝塞尔过渡，判定阈值为相邻帧 50 音分且两侧中值电平差 75 音分）、音符与音素边界处的频谱插值（±3 帧、升余弦加权）、以及 Mel 频谱上的时频高斯平滑（时间 / 频率两轴）。每个参数拥有独立曲线与各自的单位刻度；空曲线表示「常量」，跟随检查器滑块取值，标题栏在手动与自动之间切换。预设（关闭 / 温和 / 标准 / 强烈）可一键套用一组经过验证的取值。所有参数默认关闭，旧工程输出逐位不变。
  • Anchor strength on automation curves — every anchor on the pitch and timbre curves now carries a strength value (0–100, default 100): 100 makes the curve pass exactly through the anchor, 0 pulls it onto the straight line between its neighbours, and values in between "hint" a shape without locking it (a dashed guide shows the gap). Hold the right mouse button on an anchor to adjust strength (horizontal) and smoothing (vertical) with a live HUD, or select an anchor and type an exact value in the inspector. Parameter labels, inspector rows and preset dropdowns now use in-app hover cards instead of native tooltips.自动化曲线锚点强度——音高与音色曲线上的每个锚点新增强度值（0–100，默认 100）：100 使曲线精确经过锚点，0 把曲线拉向两侧锚点的连线，中间值相当于「暗示」而不锁定形状（画布上用虚线标出偏移）。右键按住锚点可拖动调整强度（左右）与平滑（上下），指针旁实时显示读数；也可选中锚点后在检查器中精确输入数值。参数标签、检查器行与预设下拉改用应用内悬浮提示卡，不再使用原生提示。
  • Model download retry & clearer GPU diagnostics — a failed model download now offers an in-place Retry button instead of requiring the window to be closed and reopened, and GPU capability probing now explains why detection failed.模型下载重试与更清晰的 GPU 诊断——模型下载失败时窗口内直接提供「重试」按钮，无需关闭重开；GPU 能力探测失败时会说明原因。
  • Keyboard & screen-reader access to the canvases — the timeline and pitch canvases are now focusable and announce selection and value changes to screen readers.画布的键盘与读屏访问——时间线与音高画布现可键盘聚焦，并向读屏软件播报选中与数值变化。

Performance 性能优化

  • Timbre edits no longer re-run diffusion (Mel-level cache) — the spectral post-processing only rewrites the Mel spectrogram fed to the vocoder, so changing a timbre curve now reuses the cached diffusion output and re-runs the vocoder alone instead of the whole diffusion loop. Cache keys are split in two layers (diffusion input vs. Mel + post-processing hash, 8 entries / 384 MB LRU); pitch curve edits still trigger full re-inference.改音色不再重跑扩散（Mel 级缓存）——频谱后处理只改写送进声码器的 Mel 频谱，因此改动音色曲线时现复用缓存的扩散结果，只重跑声码器，而不再从扩散循环重来。缓存键拆成两层（扩散输入 vs. Mel + 后处理哈希，8 条 / 384 MB LRU）；音高曲线改动仍会重新推理。
  • Streaming preview for long fragments in the fragment editor — fragments longer than 20 s, or containing rests ≥ 1.5 s, now emit audio chunk by chunk while inference is still running, instead of waiting for the whole fragment to finish. Regions are emitted in timeline order (out-of-order completions are buffered), rests between regions are padded with silence, 2 s overlaps keep the earlier region and fade the later one in over 15 ms.分片编辑器长分片流式预览——超过 20 秒、或含 ≥ 1.5 秒长休止的分片现可在推理过程中边算边播，不必等整段推理结束。各 region 按时间线顺序发射（乱序完成的先缓冲），region 间的休止补零静音，2 秒重叠保留前序、后续以 15 ms 渐变切入。
  • Faster splash and cold start — the splash screen is now drawn in the main process from a pre-rendered bitmap (BaseWindow + ImageView): no renderer process, no JavaScript, no IPC round-trip, and the version / channel / build date are baked into the image at build time. Crash-log rotation, log streaming and the console code-page switch are deferred until after the window is up.启动画面与冷启动加速——启动画面改由主进程直接绘制预渲染位图（BaseWindow + ImageView）：不启动渲染进程、不执行 JS、无 IPC 往返，版本号 / 渠道 / 构建时间在构建期烘进位图。崩溃日志轮转、日志流与控制台代码页切换均推迟到窗口出现之后。
  • Smaller install footprint — the packaged app no longer ships onnxruntime binaries for other platforms (macOS / Linux / win32-arm64), the unused TensorFlow.js meta / layers / webgl packages, the per-window asyncify / jspi ONNX Runtime loaders, source maps and node_modules/.cache. The Windows installer shrank from 226 MB to 136 MB (−40%) and the installed footprint drops by roughly 700 MB, which also shortens cold-start I/O and antivirus scanning.安装体积进一步缩小——打包产物不再包含其它平台的 onnxruntime 二进制（macOS / Linux / win32-arm64）、未使用的 TensorFlow.js meta / layers / webgl 包、每窗口重复的 asyncify / jspi ONNX Runtime loader、source map 与 node_modules/.cache。Windows 安装包从 226 MB 降到 136 MB（−40%），安装后体积减少约 700 MB，冷启动 I/O 与杀软扫描时间同步缩短。
  • Post-processing and diffusion loop — the autocorrelation sum in spectral post-processing now uses a prefix table (O(n) per frame → O(1), ~1.3× faster on that stage, numerically identical), and the diffusion loop reuses a pre-allocated prediction scratch buffer instead of allocating 1–2 MB per step.后处理与扩散循环——频谱后处理的自相关平方和改用前缀表（每帧 O(n) → O(1)，该阶段约快 1.3 倍，数值逐位一致）；扩散循环复用预分配的预测暂存缓冲，不再每步分配 1–2 MB。

Bug Fixes 缺陷修复

  • Fixed the auto-BPM detector flipping between a tempo and its double/half — the old estimator correlated raw energy, so accents buried weak beats by orders of magnitude and a 120 BPM song came back as 60; it also rounded to whole BPM, which drifts several seconds over a long take. The detector now works on a log-compressed envelope with a normalized autocorrelation, a time-based analysis window (identical at 24/44.1/48 kHz), sub-frame peak refinement and an explicit octave decision. Measured on synthetic click tracks from 55 to 180 BPM: 18/18 within 3%, versus 9/18 before. A pure two-beat pattern is still reported at the slower tempo, because that reading is physically indistinguishable — type the tempo manually if you want the fast one.修复自动 BPM 检测在一倍/一半之间摇摆——旧估计器直接对能量做相关，重音把弱拍压了几个数量级，120 BPM 的歌会测成 60；结果还四舍五入到整数，长曲子末尾会漂好几秒。新检测器改用对数压缩包络 + 归一化自相关，分析窗按时间定长（24/44.1/48 kHz 表现一致），峰值用亚帧插值细化，并显式做倍频裁决。用 55–180 BPM 的合成节拍轨实测：18/18 误差在 3% 以内，旧版只有 9/18。纯粹的"两拍一循环"仍会报慢的那侧——这种信号在物理上与快一倍不可区分，想要快的一侧请手动填写。
  • Fixed extracted notes drifting away from the waveform — four separate time bases were in play: the waveform, playhead and scroll range used a hard-coded 120 BPM while notes, the F0 curve and the preview used the piano-roll BPM; editing the BPM field only wrote to the settings store, so the grid stayed at the old tempo until the next extraction; the piano roll was created from the 120 constant after the audio decoded, so a window whose panel already showed the saved 96 opened on a 120 grid; and the detector-timeline correction extrapolated from the first two frames, so a jittery first frame could stretch or squeeze the whole take. All layers now read one BPM source, the BPM field updates the roll immediately, the roll starts from the saved tempo, and the correction uses a median frame step clamped to a plausible range.修复提取出的音符与波形越走越偏——此前同时存在四套时间基准：波形、播放头与滚动范围用写死的 120 BPM，而音符、F0 曲线与试听用卷帘的 BPM；在提取面板里改 BPM 只写进设置，网格要等下次提取才更新；卷帘在音频解码完成后才按常量 120 创建，于是"面板显示已保存的 96、网格却按 120 画"在窗口打开那一刻就成立；检测器时间轴校正又只按首两帧的步长外推，首帧一抖就会把整段拉长或压缩。现在所有层读同一个 BPM，改 BPM 立即更新卷帘，卷帘按已保存的 BPM 初始化，校正改用中位帧步长并夹在合理区间内。
  • Fixed wrong measure lines and measure numbers in compound meters — the code treated timeSignature[0] as "beats per measure", but MIDI beats are quarter notes, so 6/8 was drawn as 6 beats per bar instead of 3 and every measure line after the first landed in the wrong place. 9/8 (4.5), 12/8 (6) and 2/2 (4) are now converted with num × 4 / den, and the fragment label's measure range uses the same function.修复复合拍号下的小节线与小节编号错误——代码把 timeSignature[0] 当成了"每小节拍数"，但 MIDI 的拍是四分音符，于是 6/8 被画成每小节 6 拍（应为 3 拍），第一小节之后的每条小节线都错位。现在 9/8（4.5 拍）、12/8（6 拍）、2/2（4 拍）都按 分子 × 4 / 分母 换算，片段标签上的小节范围也用同一个函数。
  • Fixed MIDI import writing note durations with a hard-coded 120 BPM — importing a MIDI file into a 96 BPM project produced a singer data block ~20% too short, so the imported take no longer matched the audio. The conversion now uses the project BPM.修复MIDI 导入用写死的 120 BPM 写音符时长——把 MIDI 导入 96 BPM 的工程时，生成的歌手数据整体短约 20%，导入结果与音频对不上。现改用工程 BPM 换算。
  • Fixed the playhead consistently running ahead of the audio — the Web Audio clock marks when a sample is rendered, but the sound still has to pass the device buffer (measured 20–120 ms on Windows). The playhead, timecode, pause position and hit testing now use an audible clock derived from outputLatency (falling back to baseLatency) with EMA smoothing, while scheduling keeps using the render clock so compensation is never counted twice.修复播放头稳定跑在声音前面——Web Audio 时钟标记的是渲染时刻，声音还要过设备缓冲才到喇叭（Windows 实测 20–120 ms）。播放头、时间码、暂停位置与命中测试现改用由 outputLatency（退化到 baseLatency）推导并做 EMA 平滑的可听时钟；调度侧仍使用渲染时钟，避免补偿量被重复计入。
  • Fixed the playhead not returning to zero when dragged past the left edge — it stopped 0.08–0.13 s in, and the faster the drag the larger the residue. Dragging now tracks mousemove / mouseup on the window and clamps to the real boundary, with a blur guard so the drag state cannot get stuck.修复播放头拖出左边界后不归零——此前会停在 0.08–0.13 秒处，拖得越快残留越大。拖拽现改用 window 级 mousemove / mouseup 跟踪并夹紧到真实边界，另有失焦兜底避免拖拽状态卡死。
  • Fixed long rests stalling streaming preview — when one fragment was split into several regions around long rests, the chunk ordering key used only the fragment start, so later regions competed as if they began at 0 and the playhead sat in "waiting for inference" while the progress bar ran ahead. The key now includes the region's first note position, and offset sequences are asserted monotonic in regression tests.修复长休止导致流式预览长时间卡在「等待推理」——同一分片被长休止切成多个 region 时，chunk 排序键只算了分片起点，后段 region 被当成从 0 开始抢推理顺序，播放头停在原地而进度条已跑远。排序键现计入各 region 的首音符位置，并在回归测试中断言偏移序列单调。
  • Fixed wrong pitch in later segments of a fragment preview — the multi-segment synthesis path dropped the pitch-curve time offset, so every segment read F0 from frame 0 of the whole fragment; drawn pitch curves, vibrato and F0 smoothing were shifted on everything after the first segment. The offset is now passed through, so each segment indexes the curve at its absolute frame position.修复分片预览后续段音高错位——多 segment 合成路径丢弃了音高曲线的时间偏移，导致每一段都从整条曲线的第 0 帧取 F0；第一段之后的歌词手绘音高、颤音与 F0 平滑整体错位。偏移现正确透传，各段按绝对帧位索引曲线。
  • Fixed the Auto Shift checkbox showing as enabled while the pipeline treated it as off — the toolbar checkbox in both the main window and the fragment editor defaulted to checked while the pipeline and MCP defaults were false. It now defaults to unchecked, and the export dialog's fallback value matches.修复 Auto Shift 复选框显示已启用、实际未生效——主窗口与分片编辑器工具栏的复选框此前默认勾选，而管线与 MCP 的缺省值是 false。现改为默认不勾选，导出对话框的回退值同步对齐。
  • Fixed singer list rows and timeline rows being misaligned — the singer list (DOM) and the fragment timeline (canvas) now both take their row height from a single source published as CSS variables, instead of the stylesheet hard-coding a different value.修复歌手列表与时间线行高不齐——歌手列表（DOM）与分片时间线（canvas）的行高现统一由单一真源发布为 CSS 变量，样式表不再写死另一个值。
  • Fixed the pause / play button icon disappearing after certain actions — label updates wrote to the whole button node and wiped the injected SVG icon; only the text node is replaced now.修复暂停 / 播放按钮图标在某些操作后消失——更新文案时写入整个按钮节点会清掉已注入的 SVG 图标；现只替换文本节点。
  • Fixed clicking the main timeline failing to seek unless the pointer was dragged — mouse-down, double-click, context menu and hover hit tests now all use the same virtual scroll coordinates.修复主时间线点击定位不生效、必须拖动一下——按下、双击、右键与悬停的命中测试现统一使用虚拟滚动坐标。
  • Fixed overlapping or out-of-order streaming chunks in the fragment editor after an underrun resume — chunk callbacks are now serialized through a promise chain, with a 0.3 s watchdog margin and an absolute elapsed baseline for the scheduler.修复分片编辑器 underrun 恢复后流式 chunk 重叠 / 乱序——chunk 回调现经 promise 串行化，调度器使用 0.3 秒看门狗余量与绝对时间基准。
  • Fixed the fragment editor becoming unresponsive after a synthesis failure — the error path now resets the playing state and the rAF loop, so the next click works again.修复合成失败后分片编辑器点击无响应——错误路径现复位播放状态与 rAF 循环，下一次点击即可正常响应。
  • Fixed background inference penalising cancelled jobs — SUPERSEDED / CANCELLED results are now classified as a skip instead of a failure, so an interrupted fragment no longer triggers a 15 s cooldown before the next attempt.修复后台推理把取消 / 被取代当成失败并冷却 15 秒——SUPERSEDED / CANCELLED 现归类为跳过，被打断的分片不会再把后续推理推迟 15 秒。
  • Fixed Dynamic Threshold having no effect at percentiles ≥ 0.992 — the old floor-based implementation collapsed to a no-op for high percentiles at melDim=128; it now uses an interpolated quantile.修复动态阈值在百分位 ≥ 0.992 时完全无效——旧的向下取整实现在 melDim=128 且百分位偏高时退化为空操作，现改用插值分位数。
  • Fixed WSOLA crossfade producing a non-monotonic time warp — the aligned frame index could step backwards, stretching or compressing up to ±240 ms around chunk boundaries. The aligned index is now enforced monotonic.修复WSOLA 交叉淡变产生非单调时间扭曲——对齐帧索引可能倒退，在 chunk 边界附近造成最多 ±240 ms 的伸缩。对齐索引现强制单调。
  • Fixed streaming mixes silently zero-filling missing frames — the multi-stream path now asserts that committed frames equal total frames before mixing, so a short render surfaces as an error instead of a silent gap at the end.修复流式混音对缺失帧静默补零——多流路径在混音前断言已提交帧数等于总帧数，渲染不足会显式报错，而不是在末尾留下无声缺口。
  • Fixed synthesis cache not keyed on seed and Q-Drift — changing the fixed noise seed could replay audio rendered with the previous seed. All derived cache keys now include the seed and Q-Drift dimensions.修复合成缓存键未包含种子与 Q-Drift——修改固定噪声种子后可能重放上一次种子渲染的音频。所有派生缓存键现包含种子与 Q-Drift 维度。
  • Fixed FP16 drift correction being enabled on unsupported execution providers — Q-Drift is now explicitly limited to DML and TensorRT-RTX, where its calibration holds.修复FP16 漂移校正在不支持的执行提供器上仍被启用——Q-Drift 现明确只在 DML 与 TensorRT-RTX 上生效，其校准在这两条路径上成立。
  • Fixed the interface losing all styling when a theme stylesheet fails to load — a static :root fallback sheet is now bundled, so the window remains usable instead of rendering unstyled.修复主题样式表加载失败时界面完全没有样式——现内置静态 :root 兜底样式表，窗口仍可正常使用。
  • Fixed version and label inconsistencies — the version shown in the UI now always comes from the application build instead of hard-coded strings, and several missing Chinese / English strings were filled in. Note-edge resize handles also got a larger minimum hot zone (4 → 6 px).修复版本号与文案不一致——界面显示的版本号统一取自应用自身版本，不再有硬编码值，并补齐若干缺失的中英文案。音符边缘的缩放热区下限也从 4 px 提高到 6 px。

Security 安全

  • Path allow-list hardened — allowed paths are now canonicalized with realpath before comparison (blocking symlinks that point outside an authorized directory), Windows 8.3 short names are expanded, and system paths are denied explicitly.路径白名单加固——允许路径在比较前先经 realpath 规范化（阻断指向授权目录之外的软链），展开 Windows 8.3 短文件名，并显式拒绝系统路径。
  • Renderer sandbox and least-privilege preload — renderers now run with sandbox: true, and each window's preload only exposes the APIs that window needs; trimmed methods throw an explicit error instead of existing silently.渲染进程沙箱与最小权限 preload——渲染进程启用 sandbox: true，每个窗口的 preload 只暴露该窗口需要的 API；被裁剪的方法会显式抛错，而不是静默存在。
  • Plugin runner hardening — plugin workers run with resource limits, and manifest.permissions is enforced at module load: a plugin that does not declare the permissions it uses is not enabled.插件运行器加固——插件 worker 启用资源上限，并在模块加载时强制校验 manifest.permissions：未声明所需权限的插件不会被启用。
  • IPC error sanitization — errors returned to the renderer are stripped of stack traces and absolute paths, so failures can no longer leak the file system layout.IPC 错误脱敏——返回渲染进程的错误会去掉堆栈与绝对路径，失败信息不再泄漏文件系统结构。
