Model Updates 模型更新

This page tracks notable changes to the ONNX models and the inference pipeline shipped with SXSEditor. Most entries describe exported ONNX artifacts and how they are executed on the DirectML (DML) / WebNN / CPU execution providers. For application-level changes, see Application Updates.

本页追踪 SXSEditor 内置 ONNX 模型与推理管线的重大变更。多数条目描述导出的 ONNX 产物及其在 DirectML (DML) / WebNN / CPU 执行提供者上的执行方式。应用层变更请见 应用更新。

ℹ️

Model files are not stored in the Git repository (they are git-ignored). They are downloaded automatically on first launch, or placed manually in onnx_models/. See FAQ for download troubleshooting.

模型文件不包含在 Git 仓库中（已被 gitignore）。首次启动时会自动下载，也可手动放入 onnx_models/。下载问题请见 FAQ。

Vocoder 声码器

  • SiFiGAN vocoder support — a second vocoder (SiFiGAN) is now available alongside the default Vocos-style vocoder. SiFiGAN expects 200 Hz mel (hop=120); the SVS pipeline produces 50 Hz mel (hop=480), so runVocoderChunked now performs 4× nearest-neighbor time-dimension upsampling of mel and f0 before feeding SiFiGAN. The output length satisfies effectiveTotalFrames × 120 == totalFrames × 480, matching the default vocoder.SiFiGAN 声码器支持——在默认 Vocos 风格声码器之外新增 SiFiGAN 声码器。SiFiGAN 期望 200 Hz mel（hop=120），SVS 管线产出 50 Hz mel（hop=480），因此 runVocoderChunked 在送入 SiFiGAN 前对 mel 和 f0 做 4× 最近邻时间维度上采样。输出长度满足 effectiveTotalFrames × 120 == totalFrames × 480，与默认声码器一致。
  • SiFiGAN mel_proj retrained on full GTSinger — the mel_proj MLP (mapping 128-D SVS mel → 43-D mcep+bap features) was retrained on the full GTSinger dataset (2832 files, 2913 valid, 1.45M frames) with cosine annealing LR for 600 epochs (final L1 ≈ 0.18), eliminating the high-frequency artifacts caused by the original random initialization.SiFiGAN mel_proj 全量重训——mel_proj MLP（128-D SVS mel → 43-D mcep+bap）在完整 GTSinger 数据集（2832 文件，2913 有效，1.45M 帧）上以余弦退火学习率重训 600 轮（最终 L1 ≈ 0.18），消除了原始随机初始化导致的高频伪影。
  • SiFiGAN path fallback — if SiFiGAN ONNX/stats files are missing from the precision subdirectory (e.g. fp16/), the loader falls back to the onnx_models/ root directory.SiFiGAN 路径回退——若精度子目录（如 fp16/）中找不到 SiFiGAN 的 ONNX/stats 文件，加载器会回退到 onnx_models/ 根目录。
  • SiFiGAN precision detection by filename — precision is detected from the filename pattern (sifigan_vocoder_dml_fp16.onnx → FP16) rather than file size, avoiding misjudgment on MLP variants.SiFiGAN 按文件名检测精度——根据文件名模式（sifigan_vocoder_dml_fp16.onnx → FP16）而非文件大小判断精度，避免 MLP 变体误判。
  • Vocos overlap-add reshape fix — VocosFullWrapper._overlap_add now uses frames.reshape(B, num_ov, hop, T).transpose(1, 2) (correct index n = j*hop + h) instead of the previous frames.reshape(B, hop, num_ov, T) (incorrect index n = h*num_ov + j). The wrong order scrambled overlap levels, produced zeros in the window envelope (min=0.0 vs correct 0.75), and triggered division-by-zero output explosion (std=61, max=4482). PyTorch-vs-ONNX SNR improved from −75.35 dB to 84.24 dB.Vocos overlap-add reshape 修复——VocosFullWrapper._overlap_add 改用 frames.reshape(B, num_ov, hop, T).transpose(1, 2)（正确索引 n = j*hop + h），替换原先的 frames.reshape(B, hop, num_ov, T)（错误索引 n = h*num_ov + j）。错误顺序打乱了 overlap 层级，使 window envelope 出现零值（min=0.0 vs 正确 0.75），触发除零导致输出爆炸（std=61, max=4482）。PyTorch 与 ONNX 的 SNR 从 −75.35 dB 提升到 84.24 dB。
  • Vocoder expects normalized mel — the Vocos vocoder expects normalized mel (mean=0, std=1), consistent with the official PyTorch soulxsinger.py. No denormalization is applied before Vocos inference. SiFiGAN has its own mel_proj and is not denormalized either.声码器期望标准化 mel——Vocos 声码器期望标准化 mel（mean=0, std=1），与官方 PyTorch soulxsinger.py 一致。Vocos 推理前不做反标准化。SiFiGAN 有自己的 mel_proj，同样不反标准化。
  • autoShift f0Shift applied to three places — f0Shift from autoShift is now applied to f0Hz (vocoder f0 input), f0Ids (diffusion condition), and notePitchSeq (encoder pitch embedding) together. Previously applying it to only a subset caused vocoder f0 / diffusion mel mismatch and garbled pronunciation.autoShift f0Shift 三处同步——autoShift 产生的 f0Shift 现在同时应用到 f0Hz（vocoder f0 输入）、f0Ids（扩散条件）和 notePitchSeq（编码器音高 embedding）。之前只应用到部分位置会导致 vocoder f0 与扩散 mel 不匹配，咬字不清。
  • autoShift clamping ranges per vocoder — the f0Shift clamp range is now vocoder-aware: SiFiGAN uses [28, 84], others use [28, 88].autoShift 钳幅随声码器调整——f0Shift 钳幅现在按声码器类型选择：SiFiGAN 用 [28, 84]，其他用 [28, 88]。

Diffusion (diff_step) 扩散模型（diff_step）

  • FP32 re-export with Olive DML optimization — the FP32 diff_step model was re-exported with opset=20 and optimized via Olive (PeepholeOptimizer with save_as_external_data=True, onnx.save_model instead of shutil.copy2 to avoid file-size doubling, and a post-processing step resolve_neg1_in_reshape_shapes to resolve the three -1 values imported from export_shared.py). The optimized model now runs on the DML EP with COS=1.000000, SNR=112.95 dB, no NaNs.FP32 重导出 + Olive DML 优化——FP32 diff_step 模型以 opset=20 重新导出并通过 Olive 优化（PeepholeOptimizer 启用 save_as_external_data=True，使用 onnx.save_model 替代 shutil.copy2 避免文件体积翻倍，并新增后处理步骤 resolve_neg1_in_reshape_shapes 以解析从 export_shared.py 引入的 3 个 -1 值）。优化后模型在 DML EP 上运行，COS=1.000000，SNR=112.95 dB，无 NaN。
  • Precomputed RoPE tables + dynamic Slice — diffusion models now precompute the full cos/sin RoPE tables of shape [1, 4096, 64] and use dynamic Slice instead of Range(0, T, 1). The previous ConstantOfShape + CumSum and dynamic Range operators produced NaN on the DML backend for large dynamic shapes; the new approach avoids that entirely.预算 RoPE 表 + 动态 Slice——扩散模型现在预算完整 cos/sin RoPE 表（形状 [1, 4096, 64]），使用动态 Slice 替代 Range(0, T, 1)。此前的 ConstantOfShape + CumSum 与动态 Range 算子在大动态形状下会在 DML 后端产生 NaN；新方案彻底规避了该问题。
  • Independent diff_step precision detection — diff_step precision is now detected independently (filename pattern) instead of inferred from the vocoder. This fixes "electrical noise" caused by an isFP16 mismatch and adds a W16A32 → FP32 fallback path.diff_step 精度独立检测——diff_step 精度现在按文件名独立检测，不再由 vocoder 推断。修复了由 isFP16 不匹配导致的"电流声"，并新增 W16A32 → FP32 回退路径。
  • W16A32 input Casts — W16A32 models (FP16 weights, FP32 activations) now include explicit Cast nodes that cast FP16 inputs back to FP32 for diff_step / vocoder, preventing DML input-type errors.W16A32 输入 Cast——W16A32 模型（FP16 权重，FP32 激活）新增显式 Cast 节点，将 FP16 输入转回 FP32 送入 diff_step / vocoder，防止 DML 输入类型错误。
  • Unconditional branch sequence length fix — the unconditional diffusion branch now uses a target-only sequence length (excluding prompt frames) with matching position encoding. Previously including prompt frames caused RoPE position-encoding errors, leading to CFG guidance direction errors and muffled articulation.无条件分支序列长度修复——无条件扩散分支现在使用仅目标序列长度（不含提示帧），位置编码匹配。之前包含提示帧会导致 RoPE 位置编码错误，使 CFG 引导方向错误、咬字沉闷。

mel_transform mel_transform

  • Cooley-Tukey FFT via MatMul decomposition — the mel_transform now uses a Cooley-Tukey FFT (N=1920 → 64×30) implemented via MatMul decomposition, replacing the direct Conv1D DFT. The direct DFT caused O(√N) ≈ 43.8ε error amplified by log() compression (SNR=49.86 dB); the new approach reduces error to O(√64 + √30) ≈ 13.5ε and improves SNR to 83.54 dB.Cooley-Tukey FFT MatMul 分解——mel_transform 改用基于 MatMul 分解实现的 Cooley-Tukey FFT（N=1920 → 64×30），替代直接 Conv1D DFT。直接 DFT 产生 O(√N) ≈ 43.8ε 误差并被 log() 压缩放大（SNR=49.86 dB）；新方案将误差降到 O(√64 + √30) ≈ 13.5ε，SNR 提升到 83.54 dB。
  • 9-step ONNX graph — the mel_transform ONNX graph now follows the strict sequence: Gather window → Reshape → DFT64 → Twiddle → DFT30 → |X|² → Onesided → Sqrt. The Reshape transposes [k1, k2] → [k2, k1] so the index k = k1 + 64·k2 is correct.9 步 ONNX 图——mel_transform ONNX 图现在严格遵循：Gather 窗口 → Reshape → DFT64 → Twiddle → DFT30 → |X|² → Onesided → Sqrt。Reshape 将 [k1, k2] 转置为 [k2, k1]，保证索引 k = k1 + 64·k2 正确。
  • Dynamic input shapes — mel_transform is now exported with dynamo=True + dynamic_shapes, handling reference audio longer than 24000 samples. The previous static [1, 24000] shape caused fallback to a JS implementation that produced NaN ptMelData for longer references, contaminating the diffusion chain.动态输入形状——mel_transform 现以 dynamo=True + dynamic_shapes 导出，可处理超过 24000 样本的参考音频。之前的静态 [1, 24000] 形状会回退到 JS 实现，对更长参考产生 NaN ptMelData，污染扩散链。

CFG & Pipeline CFG 与管线

  • CFG rescale Bessel-corrected std — the CFG rescale calculation now uses Bessel-corrected sample standard deviation (N−1 denominator) with a single epsilon in the denominator (posStd / (cfgStd + 1e-8)), aligning with the PyTorch implementation. The DML path additionally guards with Math.max(0) on variance.CFG rescale 贝塞尔校正——CFG rescale 计算改用贝塞尔校正样本标准差（N−1 分母），分母使用单一 epsilon（posStd / (cfgStd + 1e-8)），与 PyTorch 实现对齐。DML 路径额外对方差加 Math.max(0) 保护。
  • WebNN peak normalization — the WebNN inference path now applies normalizePeakTo to the final audio output, consistent with the DML path.WebNN 峰值归一化——WebNN 推理路径现在对最终音频输出应用 normalizePeakTo，与 DML 路径一致。
  • Prompt frame count formula unified — ptFrameCount for multi-segment synthesis now uses the same formula as single-segment: Math.min(50, Math.max(10, Math.floor(totalFrames * 0.1))).提示帧数公式统一——多段合成的 ptFrameCount 现在与单段使用同一公式：Math.min(50, Math.max(10, Math.floor(totalFrames * 0.1)))。
  • Context padding offset uses HOP_SIZE — the context padding sample offset in index.js now always uses HOP_SIZE (480) regardless of vocoder type, because the external totalFrames is always 50 Hz and postprocessing normalizes SiFiGAN output to a HOP_SIZE-based length.上下文 padding 偏移使用 HOP_SIZE——index.js 中的上下文 padding 采样偏移现在始终使用 HOP_SIZE (480)，与声码器类型无关，因为对外的 totalFrames 始终为 50 Hz，后处理会将 SiFiGAN 输出归一化到基于 HOP_SIZE 的长度。

Opset & Precision Strategy Opset 与精度策略

  • ONNX opset upgraded to 20 — all ONNX models are now exported at opset 20 (the maximum allowed for DML compatibility), improving DML kernel selection and Cast operator features.ONNX opset 升级到 20——所有 ONNX 模型现在以 opset 20 导出（DML 兼容的最大值），改善 DML 内核选择与 Cast 算子特性。
  • W16A32 PTQ pipeline — a W16A32 (FP16 weights + FP32 activations) post-training quantization calibration pipeline was added, providing near-FP32 quality with reduced memory usage. FP16 precision issues (underflow in low-energy consonants, OLA window truncation) are resolved by W16A32 with proper input casting.W16A32 PTQ 管线——新增 W16A32（FP16 权重 + FP32 激活）训练后量化校准管线，在降低显存占用的同时接近 FP32 质量。FP16 精度问题（低能量辅音下溢、OLA 窗口截断）由带输入 Cast 的 W16A32 解决。
  • FP8 removed — FP8 precision was removed because the ONNX Runtime DirectML EP is not compatible with FP8.移除 FP8——移除 FP8 精度，因 ONNX Runtime DirectML EP 与 FP8 不兼容。

WebNN / NPU WebNN / NPU

  • WebNN NPU inference path — a complete WebNN inference path was added, with the vocoder running in the main process on DirectML (skipVocoder mode): the renderer runs encoder + diffusion returning mel (xtData), and the main process runs _runVocoderChunked (supports both default and SiFiGAN dual-input). The vocoder is never loaded in the renderer.WebNN NPU 推理路径——新增完整 WebNN 推理路径，声码器在主进程 DML 上运行（skipVocoder 模式）：渲染进程运行 encoder + diffusion 返回 mel（xtData），主进程运行 _runVocoderChunked（支持默认与 SiFiGAN 双输入）。声码器从不加载到渲染进程。
  • SiFiGAN on WebNN — SiFiGAN vocoder support was added to the WebNN/NPU path.WebNN 上的 SiFiGAN——WebNN/NPU 路径新增 SiFiGAN 声码器支持。

Bugs Fixed 缺陷修复

  • Vocos output explosion (wavRMS=167, electrical noise) — root cause was a zero-conditioning tensor in the diffusion model combined with the _overlap_add reshape dimension-order bug. After the reshape fix, the DML/CPU output consistency improved to diff max = 0.000285.Vocos 输出爆炸（wavRMS=167，电流声）——根因是扩散模型中存在零条件张量，叠加 _overlap_add reshape 维度顺序 bug。修复 reshape 后，DML/CPU 输出一致性提升至 diff max = 0.000285。
  • Multi-chunk streaming clipping — the multi-chunk streaming path (onChunkComplete) was sending audio before normalizePeakTo, causing stream clipping. Fixed by applying normalizePeakTo per-chunk (down-scale only, when peak > 0.95).多分片流式削波——多分片流式路径（onChunkComplete）在 normalizePeakTo 之前推送音频，导致流式削波。修复方式：每分片独立应用 normalizePeakTo（仅向下缩放，peak > 0.95 时生效）。
  • Mismatched BOW/EOW tokens — fixed severe phoneme misalignment (e.g. watashino → woc(su)shibi) caused by inconsistent BOW/EOW token structures between training and inference.BOW/EOW token 不匹配——修复了由训练与推理间 BOW/EOW token 结构不一致导致的严重音素错位（如 watashino → woc(su)shibi）。
  • MIDI note dragging desync — special handling for MIDI note dragging caused desync between the mouse position and the MIDI display; removed.MIDI 音符拖动不同步——MIDI 音符拖动的特殊处理导致鼠标位置与 MIDI 显示不同步；已移除。
  • DML Reshape with -1 — the DML backend does not support -1 values in Reshape shapes (E_INVALIDARG 0x80070057); resolved -1 values during model post-processing.DML Reshape 含 -1——DML 后端不支持 Reshape shape 中出现 -1（E_INVALIDARG 0x80070057）；在模型后处理阶段解析所有 -1 值。
