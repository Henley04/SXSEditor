Model Updates 模型更新

This page tracks notable changes to the ONNX models and the inference pipeline shipped with SXSEditor, grouped by model version. For application-level changes, see Application Updates.

本页按模型版本追踪 SXSEditor 内置 ONNX 模型与推理管线的重大变更。应用层变更请见 应用更新。

ℹ️

Model files are not stored in the Git repository (they are git-ignored). They are downloaded automatically on first launch, or placed manually in onnx_models/. See FAQ for download troubleshooting.

模型文件不包含在 Git 仓库中（已被 gitignore）。首次启动时会自动下载，也可手动放入 onnx_models/。下载问题请见 FAQ。

v3 (Current) v3（当前版本）

⚠️

Upgrade immediately — RMVPE is broken in every earlier build. The F0 curve was pinned at 30 Hz for the whole clip, so Extract F0 and audio → MIDI never actually worked. Old and new RMVPE models are mutually incompatible: this build refuses the old file with INVALID_MODEL_OUTPUT instead of degrading silently. Open Model Manager → Update and update before using pitch extraction.

请立即升级——此前所有版本中的 RMVPE 都是坏的。整条 F0 曲线锁死在 30 Hz，提取 F0 与 音频转 MIDI 实际从未可用。新旧 RMVPE 模型互不兼容：本版本会以 INVALID_MODEL_OUTPUT 直接拒绝旧模型，而不是静默退化。请先打开 模型管理 → 更新模型 完成升级，再使用音高提取。

  • RMVPE F0 stuck at 30 Hz — fixed — the old preprocess/rmvpe_model.onnx emits (1, T, 360), but the detector decoded it as (T frames, 2560 classes). base = t * 2560 ran past the 541,440-element buffer within ~200 frames; out-of-range Float32Array reads return undefined, undefined > -Infinity is false, so argmax stayed at index 0 and every frame mapped to LUT[0] = 30 Hz. The first ~2 s were mis-aligned neighbouring frames (the "random jumping" before the flat line). Measured on a known melody (MIDI 60/62/64/62/67/64/60 @96 BPM): median error is now 0.58 cents (FP32) / 1.01 cents (W8), with 0 silence false positives.RMVPE F0 锁死 30 Hz——已修复——旧 preprocess/rmvpe_model.onnx 输出 (1, T, 360)，检测器却按 (T 帧, 2560 类) 解码。base = t * 2560 在约 200 帧后就越过 541,440 个元素的缓冲区；Float32Array 越界返回 undefined，undefined > -Infinity 恒假，argmax 永远停在索引 0，每帧都映射到 LUT[0] = 30 Hz。最前 ~2 秒读到的是错位的邻帧数据（也就是平线之前那段乱跳）。用已知旋律（MIDI 60/62/64/62/67/64/60 @96 BPM）实测：中位误差现为 0.58 音分（FP32）/ 1.01 音分（W8），静音假阳性 0。
  • New RMVPE I/O contract — input is audio (1, N) with dynamic length (the mel frame count must be a multiple of 32; the app zero-pads automatically), output is salience (1, T, 360). Decoding is argmax → ±4-bin weighted cents → f0 = 10·2^(cents/1200), with max(salience) ≤ 0.03 treated as unvoiced (f0 = 0). The previous model was hard-wired to 240,000 samples (15 s) and longer or shorter clips simply failed.RMVPE 接口变更——输入为 audio (1, N)，动态长度（mel 帧数需为 32 的倍数，应用会自动补零），输出为 salience (1, T, 360)。解码为 argmax → ±4 bin 加权 cents → f0 = 10·2^(cents/1200)，max(salience) ≤ 0.03 判为清音（f0 = 0）。旧模型固定 240,000 采样（15 秒），更长或更短的音频直接失败。
  • Per-repo version numbers — each ModelScope repository keeps its own tag sequence and was bumped by one: SoulX-Singer-onnx-directml v2, -fp16 v3, -int8 v1, -int8-dynamic v1. Model Manager compares against the tag of the precision you actually have installed, so the number shown there is the authoritative one. The INT8 build is weight-only (INT8 weights + DequantizeLinear → FP32 Conv), which keeps it compatible with the NPU profile.各仓库版本号——每个 ModelScope 仓库维护自己的标签序列，均 +1：SoulX-Singer-onnx-directml v2、-fp16 v3、-int8 v1、-int8-dynamic v1。模型管理是按你当前安装精度对应的仓库标签比较的，以那里显示的版本号为准。INT8 版本采用 weight-only 量化（INT8 权重 + DequantizeLinear → FP32 Conv），保持与 NPU 配置兼容。

v2 v2

  • TRT-RTX long-generation fix — the RoPE position cos/sin tables are now baked directly into the diffusion model's weights ([1, 8192, 64] fp16, 8192-frame capacity), removing the runtime fp32 position MatMul. TensorRT-RTX (the NvTensorRtRtx / WinML execution provider) executed that MatMul on an 11-bit mantissa grid, rounding odd-frame phases for positions beyond 2048 and producing a tail energy dip / loudness collapse on longer generations. The fix applies to every execution provider.TRT-RTX 长片段修复——RoPE 位置 cos/sin 表现在直接烘焙进扩散模型权重（[1, 8192, 64] fp16，8192 帧容量），移除了运行时的 fp32 位置 MatMul。TensorRT-RTX（NvTensorRtRtx / WinML 执行提供者）会以 11 位尾数精度执行该 MatMul，导致 2048 帧之后奇数帧相位被舍入，长片段生成出现尾部能量凹陷 / 响度塌缩。该修复对所有执行提供者生效。
  • W16A32 vocoder re-export — the vocoder has been re-exported with W16A32 precision (FP16 weights + FP32 activations) and hardware-agnostic Olive optimization. It ships as a single self-contained file, so existing download manifests remain compatible.W16A32 声码器重导出——声码器以 W16A32 精度（FP16 权重 + FP32 激活）配合硬件无关的 Olive 优化重新导出，以单文件自包含形式发布，现有下载清单保持兼容。

v1 v1

  • diff_step RoPE table baked into weights (TRT-RTX fix) — the fp16 diff_step model now ships the RoPE position table as offline-baked fp16 weight initializers ([1, 8192, 64] cos/sin tables + runtime Slice) instead of a runtime fp32 position MatMul. This root-fixes the TensorRT-RTX (NvTensorRtRtxExecutionProvider) 2048-frame boundary corruption: Myelin's fused fp32 MatMul rounded odd-frame phases on an 11-bit mantissa grid, amplifying into a tail energy dip. Measured per-frame cosine at seq = 2100 / 4096 is ≈ 0.9986+ on TRT-RTX (matching DML / CPU), and the diff_step sequence cap rises from 2047 to 8192 frames (~163.8 s).diff_step RoPE 表烘焙进权重（TRT-RTX 修复）——fp16 diff_step 模型现把 RoPE 位置表离线烘焙为 fp16 权重初始化器（[1, 8192, 64] cos/sin 表 + 运行时 Slice），不再使用运行时 fp32 位置 MatMul。根治 TensorRT-RTX（NvTensorRtRtxExecutionProvider）的 2048 帧边界错误：Myelin 融合的 fp32 MatMul 以 11 位尾数网格舍入奇数帧相位，放大为尾部能量凹陷。实测 TRT-RTX 在 seq = 2100 / 4096 的逐帧余弦 ≈ 0.9986+（与 DML / CPU 一致），diff_step 序列上限从 2047 提升至 8192 帧（约 163.8 秒）。
  • Re-optimized models for GPU — the ONNX models have been re-optimized for the DirectML GPU backend. Vocoder inference speed is now up to 6× faster.为 GPU 重新优化模型——ONNX 模型已针对 DirectML GPU 后端重新优化。声码器推理速度现在最高提升 6 倍。
  • ONNX opset upgraded to 20 — all models are now exported at opset 20 (the maximum allowed for DirectML compatibility), improving GPU kernel selection.ONNX opset 升级到 20——所有模型现在以 opset 20 导出（DirectML 兼容的最大值），改善 GPU 内核选择。
  • W16A32 quantization — added a W16A32 precision (FP16 weights + FP32 activations) that delivers near-FP32 quality with lower memory usage, resolving FP16 underflow issues in low-energy consonants.W16A32 量化——新增 W16A32 精度（FP16 权重 + FP32 激活），在降低显存占用的同时接近 FP32 质量，解决低能量辅音的 FP16 下溢问题。
  • SiFiGAN vocoder option — a second vocoder (SiFiGAN) is now available alongside the default Vocos-style vocoder, with automatic mel frame-rate adaptation.SiFiGAN 声码器选项——在默认 Vocos 风格声码器之外新增 SiFiGAN 声码器，自动适配 mel 帧率。
  • mel_transform precision boost — the mel spectrogram frontend now uses a Cooley-Tukey FFT implementation, improving signal-to-noise ratio from 49.86 dB to 83.54 dB.mel_transform 精度提升——mel 频谱前端改用 Cooley-Tukey FFT 实现，信噪比从 49.86 dB 提升到 83.54 dB。
  • Diffusion model GPU stability — fixed NaN output from the diffusion model on the DirectML backend by precomputing position-encoding tables, enabling stable GPU inference.扩散模型 GPU 稳定性——通过预算位置编码表修复了扩散模型在 DirectML 后端的 NaN 输出，实现稳定的 GPU 推理。
  • Fixed Vocos vocoder output explosion — resolved a reshaping bug in the vocoder's overlap-add stage that caused output explosion (electrical noise, wavRMS=167). PyTorch-vs-ONNX SNR improved from −75.35 dB to 84.24 dB.修复 Vocos 声码器输出爆炸——修复了声码器 overlap-add 阶段的 reshape 错误，该错误导致输出爆炸（电流声，wavRMS=167）。PyTorch 与 ONNX 的 SNR 从 −75.35 dB 提升到 84.24 dB。
  • FCPE pitch detector — a new ONNX-based F0 extraction model (Fast Context-Free Pitch Estimator) has been added. FCPE is now the default MIDI extraction tool, replacing Basic Pitch as the recommended option. It offers faster and more accurate F0-to-note conversion. Auto-downloaded from ModelScope. Registered as a new model group in modelRegistry.js.FCPE 音高检测器——新增基于 ONNX 的 F0 提取模型（Fast Context-Free Pitch Estimator）。FCPE 现在是默认 MIDI 提取工具，取代 Basic Pitch 成为推荐选项。它提供更快、更准确的 F0 转音符转换。从 ModelScope 自动下载。在 modelRegistry.js 中注册为新的模型组。
  • ROSVOT voice onset detection — a new ONNX-based voice onset detection model has been added. ROSVOT detects the precise onset timing of vocal segments, improving note boundary alignment during MIDI extraction from audio. Auto-downloaded from ModelScope and registered as a new model group. Current status (v2.0.2+): the ROSVOT extraction option is no longer offered in Settings — the MIDI extraction tool selector lists FCPE (default), RMVPE and Basic Pitch, and a legacy rosvot selection falls back to RMVPE. The model file is optional (required: false in the manifest) and is not part of the first-launch download.ROSVOT 发声起始检测——新增基于 ONNX 的发声起始检测模型。ROSVOT 检测人声片段的精确起始时间，改善从音频提取 MIDI 时的音符边界对齐。从 ModelScope 自动下载并注册为新的模型组。当前状态（v2.0.2+）：设置中不再提供 ROSVOT 提取选项——MIDI 提取工具选择器仅列出 FCPE（默认）、RMVPE 与 Basic Pitch，旧版保存的 rosvot 选择会回退为 RMVPE。模型文件为可选项（清单中 required: false），不属于首次启动下载范围。
  • QDIT int8 diff_step — QDIT-quantized int8 diff_step models are now supported, using a new ONNX signature with improved quantization-aware inference for better quality at int8 precision. Legacy int8 diff_step models are automatically detected on load — if a legacy model is found, a prompt suggests switching to the QDIT version for better synthesis quality.QDIT int8 diff_step——现在支持 QDIT 量化的 int8 diff_step 模型，使用新的 ONNX 签名和改进的量化感知推理，在 int8 精度下提供更好音质。加载时自动检测旧版 int8 diff_step 模型——如果检测到旧版模型，会提示切换到 QDIT 版本以获得更好的合成质量。

v0 (Deprecated) v0（已弃用）

The original model release. It is no longer provided and has been fully superseded by v1. Known limitations that led to its deprecation:

最初的模型版本。不再提供，已被 v1 完全取代。导致其弃用的已知限制：

  • Exported at ONNX opset 17/18, without GPU-specific optimization; vocoder inference was slow.以 ONNX opset 17/18 导出，未针对 GPU 优化；声码器推理速度慢。
  • Static input shapes limited reference-audio length; longer references fell back to a JS implementation that produced NaN ptMelData.静态输入形状限制了参考音频长度；更长参考会回退到产生 NaN ptMelData 的 JS 实现。
  • The diffusion model produced NaN output on the DirectML backend for large dynamic shapes.扩散模型在大动态形状下会在 DirectML 后端产生 NaN 输出。
  • The Vocos vocoder contained an overlap-add reshaping bug causing output explosion (electrical noise).Vocos 声码器存在 overlap-add reshape 错误，导致输出爆炸（电流声）。
  • FP8 precision was incompatible with the DirectML execution provider.FP8 精度与 DirectML 执行提供者不兼容。
