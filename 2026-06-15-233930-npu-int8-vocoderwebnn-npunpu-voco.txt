     NPU INT8 Vocoder & DiffStep 加载速度优化

     Context

     NPU INT8 优化后的 vocoder (462MB, 548 nodes) 和 diff_step (423MB, 1526
     nodes) 模型在 WebNN NPU 后端加载时编译超时（>120s）。根本原因是：
     1. 大量 DequantizeLinear 节点：vocoder 有 44 个，diff_step 有 207 个。每个
     DQL 节点需要 NPU 编译器单独生成 kernel。
     2. 图复杂度高：diff_step 有 1526 个节点（含 207 DQL + 各种
     Reshape/Transpose），vocoder 有 548 节点。
     3. 模型元数据冗余：ONNX 文件包含训练信息、文档字符串等无用数据，增加
     protobuf 解析时间。

     策略：预反量化 + 图简化 + 元数据清理

     核心思路是预反量化（Pre-dequantization）：将 INT8 权重预先转换为
     FP32，移除所有 DequantizeLinear 节点，大幅减少 NPU 编译器需要处理的节点数。

     当前模型数据

     ┌───────────┬───────┬────────┬───────────────┬───────┬───────┬────────────┐
     │   模型    │ 大小  │ 节点数 │   DQL 节点    │ INT8  │ FP32  │ 预反量化后 │
     │           │       │        │               │ 权重  │ 权重  │            │
     ├───────────┼───────┼────────┼───────────────┼───────┼───────┼────────────┤
     │ vocoder   │ 462MB │ 548    │ 44 (→MatMul)  │ 176MB │ 286MB │ ~990MB     │
     ├───────────┼───────┼────────┼───────────────┼───────┼───────┼────────────┤
     │           │       │        │ 207           │       │       │            │
     │ diff_step │ 423MB │ 1526   │ (160→MatMul,  │ 422MB │ 1.3MB │ ~1689MB    │
     │           │       │        │ 47→Gemm)      │       │       │            │
     └───────────┴───────┴────────┴───────────────┴───────┴───────┴────────────┘

     两个模型预反量化后均在 WebNN 2GB 单张量限制内。

     Step 2: 修改 optimize_npu_int8.py，添加后处理优化

     在现有 optimize_model() 流程之后，添加新的优化步骤：

     2a. 预反量化（Pre-dequantization）

     - 遍历所有 DequantizeLinear 节点
     - 读取 INT8 权重 × scale → 生成 FP32 权重
     - 用 FP32 权重替换原始 INT8 权重 initializer
     - 移除 DequantizeLinear 节点，将消费者节点直接连接到 FP32 权重
     - 移除 scale 和 zp initializer

     2b. 元数据清理

     - 移除 model.metadata_props
     - 移除 model.doc_string

     - 清理 value_info 中不必要的形状信息
